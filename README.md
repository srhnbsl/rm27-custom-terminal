# RM27 三维态势终端

Web 前端 + 本地 Node.js MQTT/Protobuf 桥接，使用已有 Unity 工程同源的官方 CAD 派生网格。Unity 工程及资源未修改。

## 运行

双击 `启动终端.cmd`，随后访问 http://127.0.0.1:5173 。首次启动默认是明确标识的模拟演示；选中“暂停演示”可暂停。

开发：`npm install`，`npm run dev`。检查：`npm test`、`npm run build`。完整浏览器/MQTT 测试：`node tests/browser.mjs`（需要本机 Edge；本地测试 broker 18883）。

## 已实现

- 实际 CAD 派生场地三维显示、材质颜色、鼠标旋转/平移/缩放、俯视/全场、WASD 移动。
- 机器人三维标记、血量、朝向、平滑移动、点击选择、定位；右下二维地图使用已有地图包。
- 比赛阶段/时间/双方控制度、基地/前哨站血量、金币、己方编队及选中机器人动态信息。
- 地图本地标记、比赛事件、判罚通知；事件参数作为文本显示。
- 模拟/真实数据严格分离。连接真实数据立即清空模拟状态；绝不自动回退模拟。
- 3 秒无位置更新标记过期，10 秒后隐藏位置。历史血量等保留为最后收到值；连接状态提示数据新鲜度。
- 只读 MQTT 桥接、显式服务器/机器人 ID 配置、坐标尺度/旋转/平移配置。服务仅绑定本机回环地址。

## 协议与限制

依据用户指定的《RoboMaster 2027 机甲大师高校系列赛通信协议 V1.0.0（20261029）》第二章（正文 46–74 页，PDF 物理页 47–75）。逐字段编号核对，赛前仍需同赛事服务器实际版本验证。

比赛 MQTT 服务器 `192.168.12.1:3333`，本机比赛网卡手动配置 `192.168.12.2`；MQTT clientID 使用所连接机器人的 ID，Topic 为消息名，消息体为 Protobuf v3 二进制。浏览器不能直接访问 MQTT TCP，通过本地桥接转换为 WebSocket。

`protocol.proto` 包含 GameStatus、GlobalUnitStatus、GlobalLogisticsStatus、RobotStaticStatus、RobotDynamicStatus、RobotPosition、RobotModuleStatus、Buff、Event、PenaltyInfo、MapClickInfo。只处理明确的字段编号，保留缺省值与零值的区别。

GlobalUnitStatus 的 8 个血量顺序为己方 1/3/4/7、对方 1/3/4/7。2/102 为保留位，不展示为工程机器人；1/101 为重装机器人。RobotDynamicStatus 不含 ID，只更新连接机器人。RobotPosition robot_id 按文档仅指挥手客户端收到的哨兵坐标生效；缺省归于连接机器人。不臆造对方坐标或各机器人血量上限。

**RadarInfoToClient 暂不解码**：正文写为 `repeated uint32 RadarSingleRobotInfo;`，缺少字段名/编号且与下一页消息结构不一致。等待官方有效 proto 后再加入。订阅该消息，仅显示不支持提示。

本版不包含 UDP/H.265 视频播放、键鼠控制上行、赛事专用命令上行、哨兵轨迹展示和 SLAM 在线建图。地图标记仅本地显示，15 秒后消失，不发布 MQTT 指令。不得把本版称为已完成实机验收的比赛终端。

## 场地坐标

源资源：`D:\自定义终端\RMUC_2027map_unity-main\Project\Assets\Field\field_geometry_m.ply`。

CAD 场地坐标为米，转换到 Three.js：`(x, y, z) → (x, z, -y)`。Unity 原工程使用另一换基 `(x,y,z) → (-y,z,x)`；Web 模型从同源 PLY 直接转换，因此没有重复叠加 Unity 变换。

先将协议平面坐标乘尺度，再应用逆时针旋转，最后加 X/Y 平移。坐标设置中的勾选只是用户确认记录，不是自动标定算法，不代表上游 `map_ready=false` 已通过精度验收。

地图 PNG 映射：`u=(1-x/28)*width`，`v=(1-y/15)*height`，使用地图包约定。二维底图为规则图单应展开，局部结构不保证与 CAD 精确配准。地面机器人的显示高度通过 CAD 下向求交获得；协议 z 原值保留在状态中，该显示落地不属于物理定位估计。空中机器人使用协议 z。

`convert_map.py` 将 7,071,310 个三角面转换为 358,162 个显示三角面，采用 12 mm 顶点聚类。只用于绘制，不用于尺寸、碰撞、可通行区或定位精度判断；原始模型保持不变。场地精度边界与源资源 README 相同。

## 制作规范摘录

制作规范正文第 17–18 页（PDF 物理页 18–19）S46–S50：工作电压上限 30 V；最大收纳尺寸 600×600×600 mm；比赛数据 MQTT+ProtoBuf、视频 UDP；桌面不得接触双面胶/螺丝等粘性或尖锐物；不得裸露带电线材；接入现场 RJ45 接口后测试；终端不得使用无线发射/接收装置。Web 实现不能代替硬件检录。

## 验证范围

自动验证包含：独立 wire fixture 的坐标解码、显式零值、缺省字段、蓝方血量顺序、动态属性归属、坐标变换、位置过期；本地 Aedes MQTT → Protobuf → WebSocket → 页面更新、三维模型加载、模拟切换清空、响应式截图、浏览器错误检查。尚未连接赛事服务器，尚未进行实机坐标标定或现场压力测试。

地图及派生资源沿用上游使用边界，仅本机赛事研究使用。外部分发前按源资源说明确认许可。

2027 字段语义：GlobalUnitStatus 3/8 号字段在代码示例仍名为 shield，但表格定义已改为阵地控制状态，不能当护盾。4/9 号字段为 R/B 前哨血量，按固定阵地标识显示，不能按己方/对方交换。15/16 号字段为己方/对方累计控制度。RobotDynamicStatus 4 号字段为保留位；RobotModuleStatus 11 号字段为模块化 42mm 发射机构安装权限。
